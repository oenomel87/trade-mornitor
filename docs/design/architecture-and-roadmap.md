# 구조와 확장 계획

상위 문서: [설계 개요](./README.md)

## 실행 구조

CLI 프로세스 안에서 입력 검증 → 인증 준비 → API 조회 → 정규화 → 지표 계산 → 출력 순서로 처리한다. 첫 버전에는 데몬, 웹 서버, 시세 데이터베이스, 플러그인 시스템을 만들지 않는다.

| 구성 요소 | 역할 |
| --- | --- |
| CLI | 명령·옵션 파싱, 입력 검증, 종료 코드 결정 |
| 인증 관리자 | 환경 변수 읽기, 토큰 재사용·발급·잠금 |
| Toss 클라이언트 | HTTP, 타임아웃, API 그룹별 호출 제한·재시도 |
| 시장 데이터 서비스 | 현재가·일봉·캘린더 조회, 페이지 처리, 봉 확정 판단 |
| 분석 함수 | 정규화한 일봉만 받아 지표 계산. 네트워크·파일 접근 없음 |
| 출력기 | 표와 JSON, 결측·경고·오류 표현 |
| 관심종목 저장소 | 프로필별 코드 목록·현재 선택 저장, 동시 수정 잠금·원자적 갱신·v1 이전 |

Python 3.9 이상 단일 패키지로 구현했다. argparse, http.client, Decimal 등 표준 라이브러리를 사용하며 런타임 외부 의존성은 없다. macOS/Linux를 지원하고, 소스 실행 파일은 `bin/tmon`, 패키지 진입점은 `tmon.cli:main`이다.

## 인증과 로컬 상태

- 자격 증명은 환경 변수에서만 읽고 프로젝트 안에 복사하지 않는다. 첫 버전은 `.env` 자동 탐색을 하지 않는다.
- 토큰 캐시는 OS 사용자별 캐시 디렉터리에 저장한다. 저장소 내부에는 만들지 않는다.
- 캐시 디렉터리 권한은 사용자 전용, 파일은 `0600`으로 제한하고 원자적으로 갱신한다.
- 클라이언트별 캐시·잠금 키를 사용한다. 원문 client ID를 파일명으로 사용하지 않는다.
- 토큰의 `expires_in`으로 만료를 계산하고 만료 직전에는 재발급한다. JWT 내용을 임의로 신뢰해 유효성을 판단하지 않는다.
- 프로세스 간 파일 잠금 획득 후 캐시를 다시 읽어 다른 실행이 이미 발급했는지 확인한다.
- 인증 실패 시 최신 캐시를 먼저 다시 읽는다. 토큰 무효·만료인 경우에만 재발급 및 요청 재실행을 최대 한 번 허용한다.
- 문서상 refresh token은 없다. 동일 클라이언트의 토큰 재발급은 기존 토큰을 즉시 무효화한다.
- 이 잠금은 같은 컴퓨터의 CLI 실행끼리만 조정한다. 다른 앱·컴퓨터가 같은 자격 증명을 사용하면 토큰 무효화 충돌이 여전히 가능하다.

첫 버전은 로컬 사용자 한 명의 실행을 전제로 한다. API 호출 가능한 허용 IP는 토스증권 설정에서 사전에 등록되어 있어야 한다.

근거: [인증 명세](https://developers.tossinvest.com/docs/auth).

## 호출과 오류 처리

- 현재 API 경로: 토큰 발급, 현재가, 캔들, 국내·미국 시장 캘린더, 전체 종목 목록, 랭킹으로 제한한다.
- 토큰 발급을 제외한 시장 데이터 호출은 GET만 사용한다. 주문·조건주문 클라이언트는 만들지 않는다.
- 타임아웃: 연결 5초, 읽기 15초. 명령 전체 네트워크 처리에는 60초 예산을 둔다.
- GET의 네트워크 오류·429·일시적 5xx만 최대 2회 재시도한다. 400·403·404는 재시도하지 않는다.
- 429는 `Retry-After`를 우선하며 백오프와 jitter를 적용한다. 대기시간이 남은 예산을 넘으면 실패로 종료한다.
- 정상 응답의 `X-RateLimit-*`도 반영한다. 첫 버전은 호출을 순차 실행하며 프로세스 간 전체 TPS 조정은 하지 않는다.
- 토큰 발급은 일반 GET 재시도 정책에서 제외한다. 응답 유실 시 발급 성공 여부를 알 수 없으므로 자동 반복 발급하지 않고 다음 실행의 진단 대상으로 남긴다.
- 공급자의 request ID가 있으면 오류에 보존한다. 토큰·시크릿·Authorization은 로그에서 제거한다.

근거: [Rate Limits 및 에러 응답](https://developers.tossinvest.com/docs).

## 데이터 기준

- 가격과 거래량 문자열은 Decimal 등 십진 정밀도를 보존하는 타입으로 변환한다.
- 캔들을 시간 오름차순으로 정렬하고 중복·누락·비정상 가격·음수 거래량을 검사한다.
- 휴장일이나 무거래일에 데이터를 보간하지 않는다.
- 조회 시각과 데이터 발생 시각을 분리한다. 최신 현재가와 최근 완료 일봉 종가를 같은 의미로 표기하지 않는다.
- 시장 캘린더와 문서·실응답에서 확인한 일봉 세션 기준으로 완료된 봉을 선택한다. 국내 통합 거래와 미국 시간외 세션의 포함 범위를 추측하지 않는다.
- 초기 구현은 시장 현지 당일 일봉을 장 마감 후에도 제외한다. 캘린더의 이전 영업일에 해당하는 세션이 종료됐는지도 확인하며, 결과에 이 보수적 기준을 명시한다. 거래일·시간대를 판별할 수 없으면 분석을 실패시킨다.
- 확정 여부가 불명확한 상태에서 최신 봉을 포함하는 우회 옵션은 첫 버전에 제공하지 않는다.
- 지표 계산은 수정주가 일봉으로 통일한다. 출력에 계산 기간과 기준을 포함한다.

## 구현 순서

### 1단계: 작은 CLI 완성 (구현 완료)

1. 패키징·실행명 결정, 명령 도움말·출력 계약·로컬 진단 구현
2. 인증 캐시·잠금·HTTP 오류 처리 후 선택적 연결 진단 구현
3. 현재가 조회 구현, 국내·미국 응답 및 다중 심볼 실패 동작 확인
4. 시장 캘린더·일봉 정규화·확정 규칙 확인 후 일봉 조회 구현
5. 기본 분석 구현 및 고정 데이터 검산

완료 기준은 [CLI 명세](./cli-spec.md#첫-버전-완료-기준)를 따른다. 최초 연결 검증에서는 비밀값과 계좌 정보를 출력하지 않는다.

### 2단계: 분석 대상 찾기 (핵심 기능 구현 완료)

- `search` (구현 완료): 토스증권 거래 가능 종목 목록을 24시간 캐시하고 이름·심볼 검색. [상세 설계](./search.md)
- `rank` (구현 완료): 국내·미국 거래대금·거래량·등락률 랭킹 조회. [상세 설계](./rank.md)
- `watchlist` (구현 완료): 로컬 관심종목 추가·삭제·목록과 묶음 현재가 조회. [상세 설계](./watchlist.md)
- `profile` (구현 완료): 관심종목 프로필 생성·선택·분리 조회와 기존 목록의 `default` 이전. [프로필 설계](./watchlist-profiles.md)
- `analyze`에 기간 비교·추가 지표 도입 여부를 실제 사용 후 결정

랭킹의 시장 전체 기준과 토스증권 체결 기준을 명시한다. 전체 종목 목록을 과거 시점의 전체 투자 가능 종목 목록으로 취급하지 않는다.

### 3단계: 국내 수급 분석

- `flow`: 외국인·기관 순매수와 연속 순매수 일수
- 공매도·신용·대차 시계열을 필요한 순서로 추가
- 일자별 잠정·확정·갱신 시각, 결측값 처리 도입

종목별 투자자 수급은 주식 수 기준이다. 금액으로 이름 붙이거나 현재가를 곱해 실제 순매수대금으로 표기하지 않는다. 사후 확정된 값을 이용한 과거 분석에는 정보 이용 가능 시점을 별도로 다뤄야 한다.

### 4단계: 지속 감시와 저장

- `watch`: 선택한 종목의 실시간 가격을 터미널에서 감시
- 웹소켓 재연결·구독 복원·PING 및 연결 상태 표시
- 가격·지표 조건 알림과 중복 방지
- 필요성이 확인되면 SQLite 등 로컬 데이터 저장 도입

웹소켓 시세는 누락 가능성이 있으므로 틱의 단순 합계를 완전한 거래량으로 간주하지 않는다. 봉 기반 지표는 REST 데이터로 보정하는 방안을 검증한다.

### 이후 검토

보유자산 조회, 기간 지정·대량 과거 수집, 백테스트는 별도 설계로 확장한다. 백테스트는 데이터 보존 기간, 상장폐지 종목 포괄성, 기업행사, 수급 공개 시점, 거래 비용 모델을 먼저 확인해야 한다. 매매 실행 기능은 추가하지 않는다.

## 미결정 사항

지금 답변이 필요한 차단 항목은 아니다. 각 단계에 진입할 때 결정한다.

- 설치형 배포를 실제로 사용할지 여부 (소스 직접 실행 지원 완료)
- 당일 일봉까지 포함할 수 있는 확정 규칙과 시장별 세션 처리
- 표시 자릿수 사용자 설정 지원 시점 (현재 소수점 8자리)
- 실시간 감시를 도입할 때의 관심종목 수·갱신 빈도
