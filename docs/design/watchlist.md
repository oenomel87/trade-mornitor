# 관심종목 저장·묶음 조회

2단계의 세 번째 기능이다. 로컬 사용자별 관심종목을 프로필로 나누어 관리하며, 메모·정렬 변경·묶음 분석은 이후 필요에 따라 확장한다.

이 문서는 관심종목 작업을 설명한다. 구현된 [프로필 관리와 저장 형식](./watchlist-profiles.md)에서 프로필 생성·선택·이름 변경·삭제·v1 이전 규칙을 설명한다.

```sh
tmon watchlist add 005930 005380 AAPL
tmon watchlist list
tmon watchlist quote
tmon watchlist remove AAPL
tmon watchlist --json
```

## 명령 계약

- `watchlist`만 실행하면 `watchlist list`와 같다.
- `--profile NAME`으로 대상을 지정하며 생략 시 저장된 현재 선택을 사용한다. 처음에는 `default`다. 결과에 대상 프로필을 표시한다.
- `add SYMBOL ...`: 코드를 대문자로 정규화하고 기존 순서 뒤에 추가한다. 이미 있는 코드는 중복 저장하지 않는다.
- `remove SYMBOL ...`: 해당 코드만 삭제하고 나머지 순서를 유지한다. 없는 코드는 무시하되 결과에 명시한다.
- `list`: 저장 순서대로 코드를 표시한다. 파일이 아직 없으면 빈 목록으로 정상 종료하며 파일을 만들지 않는다.
- `quote`: 저장 목록의 현재가·통화·시세 시각을 기존 현재가 API로 한 번에 조회한다. 사용자 목록은 변경하지 않는다.
- 각 프로필 목록은 중복 제거 후 최대 200개다. 개수를 초과하거나 입력 코드 형식이 잘못되면 전체 변경을 거부한다.
- 코드 형식만 로컬에서 검사한다. 실제 존재 여부·상장 상태는 저장 시 조회하지 않는다. 이름으로 찾으려면 먼저 `search`를 사용한다.
- 목록이 비어 있으면 `quote`도 API·인증 없이 `data=[]`, 종료 코드 0으로 끝난다.
- 일부 현재가가 누락되면 기존 `quote`처럼 `status=partial`, 종료 코드 5와 누락 코드를 제공한다. 모든 종목의 데이터가 없으면 오류다.
- 공통 `--json`, `--no-color`, `--help`를 지원한다. JSON의 `command`는 `watchlist`, 작업 구분은 `meta.action`이다.
- 로컬 작업 결과 `data`는 `[{"symbol":"005930"}, ...]`이며 최종 목록이다. `meta`에 저장 경로·갱신 시각·개수·추가/삭제/무시한 코드를 포함한다. `quote` 결과의 `data`는 기존 현재가 명령과 같은 구조다.

## 보관과 안전한 변경

- macOS: `~/Library/Application Support/tmon/watchlist.json`
- Linux: `$XDG_CONFIG_HOME/tmon/watchlist.json`, 미설정 또는 상대 경로이면 `~/.config/tmon/watchlist.json`
- OS 사용자 단위로 프로필과 현재 선택을 공유한다. API 계좌와 연결하지 않으며 프로젝트 폴더·토큰 캐시에 저장하지 않는다.
- v2는 `version`, `activeProfile`, `profiles`, `updatedAt`을 저장한다. 각 프로필은 `symbols`, `updatedAt`을 갖는다. 기존 v1 목록은 `default`로 읽으며 첫 실제 변경 시 원본 백업 후 이전한다.
- 폴더는 `0700`, 저장 파일은 `0600`으로 생성한다. 프로세스 간 파일 잠금과 임시 파일의 원자적 교체를 사용한다.
- 잠금 획득 후 최신 목록을 다시 읽고 변경한다. 잠금 대기는 최대 5초이며 실패하면 설정 오류로 종료한다.
- 파일 손상·지원하지 않는 버전·잘못된 목록은 설정 오류로 안내한다. 빈 목록으로 초기화하거나 기존 파일을 덮어쓰지 않는다.
- 이미 있는 코드 추가, 없는 코드 삭제처럼 실질적 변경이 없으면 파일·갱신 시각을 유지한다.
- 종목 삭제는 `remove`에 코드를 지정한다. 프로필 전체 삭제는 별도 `profile delete` 명령의 조건을 따른다.

## 검증

순서·중복·정규화, 없는 코드 삭제, 200개 한도와 전체 변경 거부, 파일 손상·버전·권한·심볼릭 링크, 동시 추가 시 유실 방지를 검증한다. 빈 목록·로컬 작업의 무인증 동작, 묶음 현재가 정렬·누락 처리, JSON과 표 출력도 확인한다. 실제 API 검증은 임시 설정 폴더에서 수행해 사용자 관심종목을 임의로 등록하지 않는다.
