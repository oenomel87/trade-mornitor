# 단기매매 추천 기능 최종 수정 작업 명세

작성일: 2026-09-07 · 상태: 구현 전 작업 명세 · 대상: `tmon recommend --horizon day|swing`

상위 문서: [설계 개요](./README.md) · 기존 설계: [추천 설계](./recommend.md) · 사용법: [추천 가이드](../recommend.md)

이 문서는 사용자가 제공한 「단기매매 추천 기능 최종 수정안」을 구현 범위, 인터페이스, 작업 순서, 검증 기준으로 정리한 것이다. 기본 변경은 PR0~PR4-B이며, 비용·누적 호가 체결·저장소·성과 검증·breakout-v2 실험은 별도 후속 범위다. 문서 작성은 구현 완료나 전략 성과 검증을 뜻하지 않는다.

## 1. 범위와 유지 계약

기존 정량 계산 분리, 최종 가격·호가·거래 상태 재검증, 실행 기록, 제외 사유 집계, AI 설명과 정량 판단 분리를 유지한다. 기존 순수 함수와 엔진을 확장하며 새 엔진이나 저장 시스템으로 전면 교체하지 않는다.

| 전략 항목 | day | swing |
| --- | --- | --- |
| 신호·비교 구간 | 완료 5분봉·직전 5개 5분봉 | 완료 일봉·직전 20개 일봉 |
| 거래량 배수 | 1.5배 이상 | 1.5배 이상 |
| 최근 20일 평균 추정 거래대금 | 100억원 이상 | 100억원 이상 |
| 스프레드 상한 | 0.30% | 0.50% |
| 돌파선 대비 진입 상한 | 1% | 3% |
| 추세 | 추가 없음 | 기존 SMA20·SMA60 및 SMA20 상승 조건 |
| 목표 | 위험폭의 1.5~2배 | 위험폭의 1.5~2배 |
| 가격 위험률 상한 | 기존 선택 옵션 유지 | 기존 선택 옵션 유지 |

- 랭킹별 기본 50개, 상세평가 기본 30개, 조사 최대 5개, 기본 출력 최대 3개를 유지한다.
- day의 거래대금·거래량·상승률 랭킹, swing의 거래대금·상승률 랭킹과 기존 `preRank` 계산을 유지한다.
- 최종 또는 추가 검증 탈락분은 최초 정량 상위 최대 5개 밖에서 충원하지 않는다.
- 상대수익률 양수와 `riskBudget`을 필수 조건으로 추가하지 않는다.
- 자동 주문·자동 손절·실시간 보유 감시는 추가하지 않는다.

### 버전과 설정 호환성

| 필드 | 계약 |
| --- | --- |
| `strategyVersion` | 기존 돌파 전략 계열 이름 `breakout-v1` 유지 |
| `codeRevision` | 정확성 수정이 적용된 코드를 식별 |
| `recommendationPolicyVersion` | 신호 고정과 사전 필터 변경 배포 시 `snapshot-v2` 추가 |
| `signalPolicy` | 원 신호 고정과 신호 수명 정책 기록 |
| `universePolicy` | 사전 필터 후 상세평가 한도 적용 정책 기록 |
| `fillModel` | 기존 최우선 매도호가·최우선 매도잔량 기반 가정 기록 |
| `relativeReturnWindowPolicy` | 신호와 같은 고정 비교 구간 정책 기록 |
| `recommendSchemaVersion` | 기존 필드 의미 유지; 호환되지 않는 출력 변경이 필요하면 증가 |
| `effectiveConfig`, `configHash` | 기존 설정 파일·CLI 옵션을 읽고 실제 적용한 신규 기본값까지 포함 |

네 가지 정책 식별자는 설정·결과·실행 기록에 남긴다. 세부 문자열, `codeRevision`의 미커밋 변경 식별 방식, 스키마 호환성은 구현 인터페이스 설계에서 확정한다. `strategyVersion`이 같아도 신호 수명·후보군·체결 가정이 달라지면 같은 실행 정책이 아니다. `day.maxSignalAgeSeconds=600`은 신규 초기 정책값이며 무영향 수정이나 검증된 최적값으로 설명하지 않는다.

PR1·PR2·PR3의 시각·신호·비교 구간 인터페이스를 먼저 함께 설계한 뒤 PR0 → PR1 → PR2 → PR3 → PR4-A → PR4-B 순서로 적용한다. PR3을 먼저 배포하고 시각·지수 구간을 나중에 맞추지 않는다. 기존 작업 트리에 일부 PR4-A 성격의 수정이 있으므로 커밋 분리 시 이 의존 순서를 명시적으로 검토한다.

각 작업은 코드·회귀 테스트·영향받는 사용 가이드·설계 문서·버전 기록을 함께 변경한다. 영향 크기와 빈도는 실행 기록으로 측정한다. 지수 수치 오차가 작다는 이유만으로 추천 순위 영향도 작다고 단정하지 않는다.

```text
세션 확인

→ 종목 정보 사전 필터
→ 상세평가 대상 확정
→ 스크리닝 공통 시각·신호 구간 확정
→ 시장별 지수 비교 자료 확보
→ 종목별 신호 계산과 최초 진입 평가
→ 스크리닝 통과 행 전체 저장
→ 정량 상위 최대 5개 선정
→ AI 뉴스·공시 설명
→ 추가 비수정 일봉 검증 완료
→ 원 신호 기준 최종 가격·호가·상태 재검증
→ 최종 유효 후보 재정렬
→ 만료 확인·출력·기록
```

추가 비수정 일봉 검증은 최초 상위 최대 5개에만 수행하며 최종 호가 재검증 전에 완료한다.

| 내부 자료 | 고정 여부 | 주요 내용 |
| --- | --- | --- |
| `SignalSnapshot` | 동일 신호에서 고정 | 입력 식별자, 돌파선, 신호 종가, 무효화 가격, 거래량 배수, 입력 구간, 상대수익률 |
| `EntryEvaluation` | 조회 때마다 재계산 | 현재가, 호가, 진입 기준가, 위험폭, 목표, 수량, 거래 상태, 각 확인 시각 |
| `RecommendationSnapshot` | 출력마다 불변 기록 | 원 신호·최종 진입 평가·설명·유효 기한·정책 및 코드 버전 |

기존 함수의 계산 경계를 활용해 자료를 분리한다. 스크리닝 행은 복사 또는 직렬화로 고정하고 이후 수정하지 않는다. 입력 정정·가격 기준 변경은 해시 또는 데이터 버전으로 구분한다.

## 4. PR0 — 기록·호출·오류 분류

### 4.1 모든 정량 통과 행 보존

`inputs['screened']`에 조사 전 정량 통과 행 전체를 저장한다. 조사 대상 밖 후보와 최종 탈락 후보도 포함한다. 각 행에서 다음 정보를 복원할 수 있어야 한다.

- 신호 입력 식별자, 돌파선, 무효화 가격, 거래량 배수.
- 상대수익률과 비교 구간.
- 최초 진입가, 위험폭, 목표 하단·상단, 수량.

최종 결과와 별개로 보존하며 최종 시세·설명 추가 과정에서 원 스크리닝 결과를 덮어쓰지 않는다.

### 4.2 종목 정보 중복 조회 제거

`Engine.evaluate()`와 `current_data()`는 사전 조회 종목 정보를 재사용해 스크리닝 중복 `/api/v1/stocks` 요청을 제거한다. 최종 상태 확인용 `current_data()`의 종목 정보·경고 재조회는 유지한다.

```text
current_data()에 남는 STOCK 그룹 요청:
  /api/v1/stocks
  /api/v1/stocks/{symbol}/warnings
```

제안의 기준 평가 경로에서 종목 상세 엔드포인트는 후보당 2회 → 1회, STOCK 그룹은 3회 → 2회로 줄어드는 것을 검증한다. 사전 다건 조회는 별도로 집계하며, 최종 재검증·만료 재시도를 포함한 실행 총호출과 혼동하지 않는다. 엔드포인트별 집계와 레이트 리밋 그룹별 집계를 모두 기록한다.

### 4.3 요청·응답·대기 관측

`RecordingClient`와 `Transport`를 연결해 성공과 실패 모두 다음 관측 정보를 기록한다.

```text
requestStartedAt
receivedAt
endpointGroup
attemptCount
rateLimitWaitSeconds
retryWaitSeconds
elapsedSeconds
success 또는 안전하게 정규화한 오류코드
```

원천 데이터 시각과 조회 시각을 구분한다. 시간 예산·대기·경과 시간에는 단조 시계, 시장 시각 비교에는 시간대가 명시된 시각을 사용한다. 토큰·인증 헤더·비밀 환경변수·민감한 원문 오류는 저장하지 않는다.

### 4.4 근거 기반 제외와 실행 상태

| 상황 | 분류 |
| --- | --- |
| 상장일 등 근거상 요구 이력이 원래 존재하지 않음 | 예상된 대상 제한 |
| 세션상 필요한 완료 봉이 아직 생성될 수 없음 | 예상된 평가 불가 |
| 있어야 할 일봉·분봉이 없고 원인 미확인 | 후보 데이터 미확인 |
| 정상 자료로 가격·거래량 조건을 평가했지만 미충족 | 정량 조건 탈락 |
| 인증·전송·공통 랭킹 등 실행 기반 실패 | 기존 실행 오류 처리 |

`insufficient-history`만으로 신규 상장으로 간주하지 않는다. `stale-daily`, `incomplete-bars`, `zero-volume-baseline`도 근거 없이 정상 후보 특성으로 재분류하지 않는다.

기존 `ok/partial/error` 및 종료 코드 계약을 유지하면서 `executionStatus`, `coverageStatus`, `expectedIneligibleCount`, `candidateDataUnavailableCount`를 추가한다. 신규 상태 필드의 값과 기존 상태·종료 코드 대응표는 PR0 구현 시 명시한다.

근거 있는 짧은 이력 후보 하나만 제외되고 다른 처리가 정상이면 `ok`·종료 코드 0이 가능하다. 설명되지 않은 필수 자료 미확인은 불완전한 평가로 표시한다. 모든 후보가 데이터 미확인인 경우 정상 후보 부재로 표시하지 않는다. 결함 비율은 분석·경보용이며 50% 초과만으로 공급자 장애를 단정하거나 이하의 미확인을 숨기지 않는다.

## 5. PR1 — 실제 시각과 완료 봉 정합성

| 필드 | 의미 |
| --- | --- |
| `phaseStartedAt` | 스크리닝 단계가 시작된 실제 공통 시각 |
| `receivedAt` | 각 API 응답을 실제 받은 시각 |
| `signalWindowEndAt` | 완료 지연을 반영해 선택한 고정 신호 구간 종료 시각 |

실제 시각과 봉 종료 시각을 같은 변수로 취급하지 않는다.

### 최신 완료 5분봉

```text
S = 정규장 분석 세션의 실제 시작 시각
P = phaseStartedAt
D = barCompletionDelaySeconds
n = floor((P - S - D) / 300초)
F = S + n × 300초
signalWindowEndAt = F
```

`n <= 0`이면 완료 5분봉이 없다. day에는 추가로 연속 완료 5분봉 6개가 필요하다. 실제 마지막 신호 봉 종료가 F인지 검사하고 필요한 최신 봉이 없으면 이전 봉으로 대체하지 않는다. 고정 305초 검사는 제거한다.

### 처리 순서

```text
receivedAt 기준 미래 봉·시각 이상 검사
→ 봉 형식·데이터 검증
→ phaseStartedAt 기준 완료 여부 확인
→ signalWindowEndAt까지 절단
→ 개수·연속성 검사
```

기존 다음 분 경계 봉 제외 정책은 유지하되 `receivedAt`으로 판단한다.

```text
완료 인정: barEndAt + D <= phaseStartedAt
구간 절단: barEndAt <= signalWindowEndAt
```

이미 지연을 반영한 `signalWindowEndAt`을 기존 실제 `now` 인수에 넣어 지연을 두 번 차감하지 않는다.

원천 최신성은 신호 구간으로 자르기 전 최신 사용 가능 봉으로 검사한다. 최신 분봉이 정상 도착했는데 고정 신호가 4분 전이라는 이유만으로 공급 지연으로 판정하지 않는다. 고정 구간의 연속성, 원천 최신성, 추천에 사용할 신호 수명을 각각 검사한다.

## 6. PR2 — 상대수익률과 지수 캐시

### 비교 구간과 단위

```text
day: [signalWindowEndAt - 30분, signalWindowEndAt)
     정확히 연속된 완료 1분봉 30개
     첫 봉 시가 → 마지막 봉 종가
swing: 신호 거래일 종가 → 정확히 5거래일 전 종가와 비교
       수익률은 과거 종가에서 신호 종가까지의 변화율
relativeReturnPct = 종목 수익률(%) - 소속 시장 지수 수익률(%)
```

종목과 지수의 시작·종료 시점이 일치해야 한다. `relativeReturnWindow`를 행에 저장하고 차이의 단위는 퍼센트포인트를 유지한다.

지수 응답은 지수용 정규화 어댑터를 거쳐 공통 시간 필터를 적용한다. 종목 캔들 함수에 원 응답을 그대로 넣지 않는다. 실제 시각 기준 완료 판정으로 진행 중 100이던 값을 나중에 완료 101인 것처럼 재사용하는 문제를 막는다.

### 캐시와 단계 공통 스냅샷

캐시 키에 최소 다음을 포함한다.

```text
market
interval
comparisonStartAt
comparisonEndAt
priceBasis
completionPolicyVersion
```

같은 스크리닝 단계의 시장별 지수 자료를 후보 평가 전에 확보한다. 필요한 구간이 없거나 조회 실패 시 시간 예산 안에서 최대 1회 재시도한다. 성공 또는 미확인 결과를 그 단계의 공통 스냅샷으로 고정하며 뒤에 평가한 후보만 다른 자료를 쓰지 않는다.

최종 단계에서는 원 신호의 상대수익률을 유지한다. 현재 지수만 새로 조회해 구간을 바꾸지 않으며 이 용도의 `final_index_cache`를 제거한다.

### 미확인 사유

`index-fetch-failed`, `index-bar-missing`, `index-data-invalid`, `stock-bars-noncontiguous`, `comparison-basis-unverified`를 구분해 기록한다. 미확인 상대수익률은 필수 탈락으로 바꾸지 않고 기존처럼 정렬에서 뒤로 배치한다. 비교 가능한 시장·후보 범위와 미확인 사유를 표시하며 양수를 필수화하지 않는다.

## 7. PR3 — 원 신호 고정과 최종 진입 재평가

### 7.1 불변 신호

스크리닝에서 `signal()`을 계산한 뒤 다음 정보를 고정한다.

```text
signalId 또는 signalInputHash
signalPolicy
signalAsOf                  기존 의미 유지
signalBarStartAt
signalBarEndAt
signalSessionDate
signalClose
breakoutLevel
invalidation
volumeRatio
relativeReturnPct
relativeReturnWindow
priceAdjustmentPolicy
```

day의 종료 시각은 신호 시작+5분이다. swing은 공급자 일봉 집계 종료 기준을 확인한 경우만 종료 시각을 기록하고 미확인 시 null로 둔다. 15:30 종료나 24시간 봉을 가정하지 않고 거래일로 유효성을 판단한다. 동일 종목·동일 봉이라도 정정 입력·가격 기준 변경을 해시 또는 데이터 버전으로 구분한다.

### 7.2 최종 조회와 재계산

| 구분 | 내용 |
| --- | --- |
| 재조회 | 시장 캘린더·세션, 종목 거래 상태, VI 등 공급자 경고, 현재가, 호가·잔량, 상한가 |
| 원 신호로 재계산 | 진입 범위, 스프레드, 가격 위험률, 목표 하단·상단, 상한가 적합성, 기존 capital 기준 수량, 최우선 호가잔량 적합성, 결과 유효 기한 |
| 고정 | 신호·상대수익률·비교 구간·거래량 배수 |

최종 단계는 새 돌파를 요구하지 않고 `signal()`을 호출하지 않는다. 신호 계산용 일봉·분봉도 다시 조회하지 않는다. 정렬은 기존 순서인 상대수익률 확인 여부 → 상대수익률 내림차순 → 거래량 배수 내림차순 → 최종 스프레드 오름차순 → 심볼 오름차순을 유지한다.

### 7.3 신호 수명

`nextBarCompletionAt`은 다음 5분봉이 완료로 인정되는 시각이며 원 신호 만료를 뜻하지 않는다. 실제 만료는 `signalValidUntil` 하나로 관리한다. 실제 검사에서 무시하는 `signalExpiresAt` 필드를 두지 않는다.

```text
day.maxSignalAgeSeconds = 600
day.signalValidUntil = min(
  signalBarEndAt + day.maxSignalAgeSeconds,
  해당 거래일 진입 평가 종료 시각
)
signalAgeSeconds = finalCheckedAt - signalBarEndAt
```

600초는 다음 봉 생성 후에도 원 신호를 제한적으로 재검증하기 위한 초기 실행 정책값이다. 기존 단계 시간 예산은 유지한다. 실제 최종 확인 시각으로 나이를 계산하며 버킷으로 내림하지 않는다. 만료 시각 이상이면 `signal-stale`로 제외하고 다른 거래일·세션으로 이월하지 않는다.

swing에는 600초 규칙을 적용하지 않는다. 신호가 실행 거래일의 직전 완료 거래일 일봉인지 확인하고 `signalValidUntil`은 해당 실행 거래일 진입 평가 종료 시각으로 둔다. 다음 거래일에는 새 직전 완료 일봉을 평가한다.

### 7.4 가격 경로 검사 범위

현재 가격·호가가 원 신호 진입 조건에 맞는지를 확인한다. 신호 발생 이후 중간에 무효화 가격을 터치하고 회복했는지는 확인하지 않는다. `signalPathCheck=not-performed`를 기록하고 현재 밴드 적합성을 “한 번도 무효화되지 않은 신호”로 표시하지 않는다.

향후 가격 경로 기반 영구 무효화는 별도 정책으로 버전 관리한다. 이번 최종 신호 재계산용 분봉 조회 제거를 미래 경로 검사용 조회까지 금지하는 규칙으로 해석하지 않는다.

### 7.5 출력 유효 기한

```text
expiresAt = min(
  최종 평가 시각 + resultSeconds,
  현재가 원천 시각 + quoteSeconds,
  호가 원천 시각 + quoteSeconds,
  종목 상태 확인 시각 + stateSeconds,
  경고 확인 시각 + stateSeconds,
  signalValidUntil,
  진입 평가 종료 시각
)
```

순차 조회한 상태·경고의 실제 확인 시각을 각각 보관한다. 마지막 조회 시각으로 모두 갱신된 것처럼 처리하지 않는다. 기존 제한된 만료 재시도는 같은 신호로 수행하며 신호 수명을 연장하지 않는다.

출력 경계에서 저장·직렬화 지연까지 고려해 만료를 확인한다. 만료 후보는 제외하거나 재검증하고 실제 출력 결과와 저장된 출력 스냅샷을 일치시킨다. 원 스크리닝 기록은 수정하지 않는다.

## 8. PR4-A — 사전 필터 후 상세평가 한도

```text
랭킹 합집합
→ 기존 preRank 정렬
→ 종목 정보 다건 조회
→ 보통주·ACTIVE·KRW·거래 제한 사전 검사
→ 통과 종목 중 detailLimit개 선정
→ 차트 기반 상세평가
```

공급자 다건 한도를 확인해 분할 조회한다. 누락·중복·잘못된 종목 매핑을 검사하고 사전 정보를 재사용한다. 최종 거래 상태 재확인은 생략하지 않는다. `inputs['preExcluded']`를 추가하고 확인된 사전 조건 탈락과 정보 미확인을 구분한다.

| 집계 | 의미 |
| --- | --- |
| `universeCount` | 랭킹 합집합 수; 통과 종목 수로 의미 변경 금지 |
| `preExcludedCount` | 확인된 사전 조건 탈락 수 |
| `precheckDataUnavailable` | 사전 정보 확인 실패 수 |
| `detailSelectedCount` | 상세평가 대상으로 선정한 수 |
| `screenedCount` | 정량 통과 수 |

사전 제외를 상세평가 제외에 중복 합산하지 않는다. 이 변경은 기준 커밋의 “먼저 상위 30개 선택” 정책을 변경하므로 구현·가이드·설계·정책 버전을 함께 수정한다. day 거래량 랭킹은 유지하며 제거 실험은 후속이다.

## 9. PR4-B — 일봉 결측과 가격·거래량 기준

### 9.1 거래일과 중간 결측

`daily_data()`·`market.history()`에서 마지막 봉이 직전 거래일인지뿐 아니라 실제 계산 구간의 중간 거래일도 확인한다. 공통 거래일 자료를 먼저 준비한다.

- 지수 일봉의 최신성·중복·필요 구간 확보 여부를 검사한다.
- 확보한 시장 캘린더 또는 거래일 캐시와의 일관성을 확인한다.
- 종목 상장 기간과 필요한 실제 거래일 수를 확인한다.

지수 날짜는 종목 결측 탐지에 활용할 수 있으나 완전한 시장 캘린더로 간주하지 않는다. 종목과 지수가 같은 날짜를 누락하면 비교만으로 발견할 수 없다. 기준 거래일 자료의 완전성을 확인하지 못하면 검사 완료로 표시하지 않는다. 실제 결측은 `daily-gap`, 기준 거래일 자체가 불명확하면 데이터 미확인으로 구분한다.

누락 봉을 유지 가격·거래량 0으로 채우지 않는다. day와 swing의 실제 계산 요구 구간을 검사하며 day에 무조건 65일을 요구하지 않는다.

### 9.2 용도별 조정 기준

| 계산 용도 | 요구 기준 |
| --- | --- |
| 돌파선·이동평균 | 현재 가격과 비교 가능한 일관된 수정 가격 |
| 과거 거래대금 추정 | 당시 비수정 종가와 대응 거래량 |
| 거래량 배수 | 기업행사 전후 단위가 일관적인 거래량 |

기존 수정 가격·반환 거래량 기반 계산의 한계를 기록한다. 가격 조정 발견만으로 거래량 조정 방식까지 확인했다고 간주하지 않는다.

초기 호출 비용을 제한하기 위해 조사 대상 최대 5개에 비수정 일봉 검증을 추가하고 최종 호가 재검증 전에 완료한다. 최근 20일 거래대금 추정을 재계산하고 확인 가능한 필수 조건을 다시 검사한다. 기준을 확인할 수 없으면 `adjustment-basis-unverified`로 기본 추천에서 제외한다. `adjusted-window` 경고만 붙여 검증 완료로 유지하지 않는다.

초기 스크리닝에서 잘못 탈락한 후보는 이 검증으로 복구되지 않는다는 한계를 남긴다. 일봉 저장소 확보 후 동일 검사를 전체 상세평가 대상 앞으로 이동하는 것은 후속이다. 추가 탈락분도 최초 상위 최대 5개 밖에서 충원하지 않으며 100억원 기준은 유지한다.

## 10. 후속 기능 — 비용과 누적 호가 체결

이번 기본 변경은 최우선 매도호가 기준 진입가, 기존 `capital` 수량 계산, 최우선 매도잔량 검사를 유지한다. 여러 호가 잔량만 합산해 통과시키지 않는다. 가격 기준 위험금액이 실제 손실 한도라는 의미를 부여하지 않는다.

누적 호가 기능은 별도 `fillModel`로 다음을 함께 구현해야 한다.

```text
밴드 안의 유효 매도호가 선택
→ 호가별 가정 체결 수량 계산
→ 총투입금액 이내 정수 수량 결정
→ 가중평균 진입가·최악 체결가격 계산
→ 위험폭·목표·수량·가격 제한 재평가

Σ(호가별 수량 × 호가가격) + 가정 매수 비용 <= capital
```

최우선호가·가중평균 체결가격·최악 체결가격은 별도 필드로 표시한다. 일부 체결가격이 밴드 밖이면 가중평균만 밴드 안이라는 이유로 허용하지 않는다. 가정 체결가격과 목표에 호가단위·상한가 처리를 적용한 뒤 위험폭과 손익비를 다시 검사한다. 이는 잔량 필터 완화가 아닌 체결 모형 변경이며 실제 체결 보장이 아니다.

비용은 수수료·세금·추가 체결 불리함을 분리하고 적용 기간·거래 조건·출처·버전을 저장한다. 과거 세율을 현재 기간에 일괄 적용하지 않는다.

```text
비용 모형 도입 → 비용 전후 손익비 기록 → 여러 비용 시나리오 비교
→ 선택적 필터 적용 → 검증 후 기본 정책 결정
```

매도호가 진입에 이미 반영된 가격 차이를 매수 스프레드로 다시 전부 가산하지 않는다. 고정 0.4%는 확정 비용이 아닌 가정 시나리오로 명시한다. 비용 때문에 탈락한다고 목표를 자동으로 높이지 않는다.

## 11. 후속 저장소와 swing 사전 계산

일봉 로컬 저장소는 종목·거래일·가격 기준·거래량 기준·원천 관측 시각·정정 이력을 저장한다. 단순 `(symbol, date)` 키에 서로 다른 조정 기준을 섞지 않는다.

수정주가는 기업행사로 과거 값이 바뀔 수 있으므로 최근 구간 대조, 조정 변화 탐지, 필요한 과거 구간 재구축 정책을 둔다. 마지막 저장일 이후만 추가하는 방식으로 끝내지 않는다. 공급자가 지원하는 페이지네이션으로 최신 구간을 조회·비교하며 지원하지 않는 “마지막 저장일 이후” 인수를 가정하지 않는다.

swing은 완료 일봉 신호를 미리 계산하고 장중에 진입 적합성을 확인하는 방향을 채택한다. 전시장 종목 목록은 기존 랭킹과 다른 후보군 정책이므로 기준일·활성 상태·상장·상장폐지 이력과 `universePolicy`를 기록한다. 사전 계산만으로 주문 가능 여부를 확정하지 않으며 장중 가격·호가·상태·밴드·수명 검증을 유지한다.

## 12. 후속 성과 수집과 백테스트

| 평가 집합 | 답하는 질문 |
| --- | --- |
| `screened` | 포착한 정량 신호 자체의 이후 가격 특성 |
| 최종 출력 스냅샷 | 실제 추천받을 수 있었던 후보의 이후 성과 |
| 실제 체결 기록 | 사용자의 실제 매매 성과 |

세 집합을 섞지 않는다. 같은 `signalId` 반복 출력의 중복 제거 규칙을 정하고 기본 신호 분석은 최초 관측 1회로 집계한다. 최종 추천 분석은 발행 시각 이후 접근 가능한 가격을 사용하며 스크리닝 가격에 체결된 것으로 처리하지 않는다.

### 진입·청산 가정

실행 모사는 세션·09:30 이후 평가(일반장 기준, 실제 세션 반영)·후보군·처리 지연·최종 가격·호가 조건을 반영한다. “다음 날 시가 진입”은 별도 일봉 신호 연구로 분리한다. 당일 고가·저가를 본 뒤 같은 날 시가 진입을 가정하지 않는다. 과거 호가·당시 랭킹이 없으면 한계를 표시하고 가짜 확정 호가나 현재 종목 목록으로 대체해 동일 전략이라고 주장하지 않는다.

운영의 `exitBy`는 참고 시각을 유지하고, 성과 검증은 별도 `exitPolicy`를 기록한다. 첫 실행 모사의 청산 규칙:

```text
목표 하단 도달: 전량 청산 시도
무효화 가격 도달: 전량 청산 시도
둘 다 미도달: 예정 보유 종료일의 종가 단일가 참여 가정
```

종가 단일가 시작은 청산 시도 시각이고 평가 가격은 단일가 종료 후 확인되는 종가다. 15:20을 접속매매 즉시 체결가격으로 처리하거나 15:25에 종가가 확정됐다고 가정하지 않는다. 실제 시각은 시장 캘린더로 결정한다. 가상 모형은 거래정지·갭·체결 불가를 반영하며 실제 청산 성공을 보장하지 않는다. 다른 시간 청산은 별도 실험이다.

### MFE·MAE·비용·검증

- MFE는 진입 이후 최대 유리 변동, MAE는 최대 불리 변동이다. 추천·가정 진입 이전 가격을 포함하지 않는다.
- swing 진입일 일봉 고가·저가에는 진입 전 움직임이 섞일 수 있으므로 진입일 분봉을 사용한다. 없으면 불확실한 범위 또는 계산 불가로 처리한다.
- 같은 봉에서 목표와 무효화 가격이 모두 관측되면 순서를 확인한다. 불가능하면 불리한 순서 또는 미확정으로 처리한다.
- 기간별 수수료·세금과 체결 모형을 사용한다. 해상도·체결 불확실성을 숨긴 고정 비용 차감만으로 실거래 성과를 확정하지 않는다.
- 당시 이용 가능했던 자료만 사용하며 생존 편향·중복 신호·겹치는 보유 기간을 관리한다.
- 조건 탐색 기간과 최종 평가 기간을 분리하고 시험한 조건·변경 이력을 보존해 과거 최적 조합만 선택하는 편향을 관리한다.

## 13. breakout-v2 독립 실험

| 실험 | 비교할 내용 |
| --- | --- |
| 거래량 랭킹 제거 | 기존 후보군 대비 누락·신규 신호와 성과 |
| 거래량 배수 중심 정렬 | 기존 상대수익률 우선 정렬 |
| 지수 추세 조건 | 소속 시장 지수의 완료 자료와 SMA20 조건 |
| 진입 상한 기준 변경 | 돌파선 기준 대 신호 종가 기준 |
| ATR 위험폭 상한 | `riskPerShare <= k × ATR14` 등 단위 명시 |
| day 진입 종료 앞당김 | 잔여 거래 시간·시간대별 성과 |
| day 5분·15분 신호 | 사용자 노출과 분리한 관찰 기록 |

동일 가격 기준의 정상 OHLC에서 20일 고가 돌파는 `close > SMA20`을 함의하지만 `SMA20 > SMA20(-5)`는 함의하지 않는다. 상승 조건 삭제는 독립 전략 변경이다. `maxLossPct`의 퍼센트 의미를 ATR 가격 단위로 바꾸지 않고 ATR 제한은 별도 이름의 설정으로 둔다.

뉴스 LLM 해석을 자동 제외 조건으로 사용하지 않는다. 구조화된 공식 사건 차단은 출처·회사 식별·시점·정정·해소 관계를 다루는 별도 설계다.
