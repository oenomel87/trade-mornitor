# snapshot-v2 구현 인터페이스 결정

작성: Codex · 2026-09-08 · 상태: 구현 지시 기준

상위 계약은 [작업 명세](./recommend-snapshot-v2-work-spec.md)다. 아래는 구현 경계를 구체화하며 전략 임계값을 변경하지 않는다.

## 공통 자료와 시계

- 기존 dict·Decimal·순수 함수 패턴을 유지한다. 신호 스냅샷은 입력 OHLCV·가격 기준·고정 구간을 정규화한 SHA-256과 독립 복사로 고정한다.
- 스크리닝 컨텍스트는 실제 `phaseStartedAt`, 세션, `signalWindowEndAt`, 비교 구간, 시장별 고정 지수 결과, 공통 거래일 자료를 가진다.
- 벽시계는 주입된 `now()`, 예산·경과 시간은 주입된 단조 `clock()`을 사용한다. 요청별 `receivedAt`은 반환 직후 취득한다.
- `completed_minutes()`는 기존 brief 호출의 기본 동작을 유지하고, 추천 전용 인수로 실제 응답 수신 시각과 고정 신호 구간을 추가한다. 완료 판정에서 지연을 중복 차감하지 않는다.
- 원천 최신성 검사에는 수신 시각 기준 최신 사용 가능 봉을 쓰고, 신호 계산에는 단계 시작 시각에 완료됐으며 고정 구간 안에 있는 봉만 쓴다.

## 신호와 최종 평가

- 스크리닝만 `signal()`을 호출한다. 최종 평가는 명시적인 원 신호 인수를 받아 `entry()`와 현재 상태 재조회만 수행한다.
- `current_data()`는 사전 종목 정보 재사용을 지원한다. 상태·경고 확인 시각을 별개로 반환하며 최종 평가에는 정보 재사용을 적용하지 않는다.
- 상대수익률은 고정 비교 자료에만 의존한다. 지수 정규화는 종목 응답 형식을 강제하지 않는 전용 어댑터에서 담당한다.
- 시장별 성공·미확인 지수 결과는 최초 조회와 최대 1회 재시도 후 고정한다. 인증 오류를 선택적 상대수익률 미확인으로 숨기지 않는다.
- 원 신호의 `signalAsOf` 의미를 유지하고 종료 시각·입력 해시·거래일·신호 수명·경로 미검사 필드를 추가한다. swing 종료 시각은 공급자 근거가 없으면 null이다.
- `inputs.screened`는 최초 진입 평가 직후 독립 복사한다. 추가 비수정 일봉 검증은 별도 자료로 기록하고 초기 결과를 수정하지 않는다.
- 최종 저장·직렬화 경계는 CLI와 Store의 실제 호출 순서를 점검해 설계한다. 저장한 결과와 실제 출력이 다르면 안 되며, 저장 실패 계약도 유지한다.

## 버전·오류·검증 근거

- 전략은 `breakout-v1`, 완성 정책은 `snapshot-v2`; 정책 식별자를 기본 설정에 넣고 실제 설정 해시에 포함한다.
- `codeRevision`은 가능한 경우 Git HEAD와 변경 여부/관련 소스 해시로 실제 작업 트리를 식별한다. Git이 없는 배포 환경에서는 소스 해시 등 명시적인 대체 식별자를 쓴다.
- 예상 제외는 근거를 포함한 별도 오류 타입 또는 분류 속성으로 구분한다. 기존 `kind=condition/data` 의미는 유지하고 세부 분류를 추가한다.
- `executionStatus`는 completed/failed, `coverageStatus`는 complete/partial/not-evaluated로 정의한다. 전체 실행 status·종료 코드는 기존 계약을 유지한다. 연구 미확인과 정량 데이터 커버리지를 혼동하지 않는다.
- 일봉 거래일은 시장 캘린더의 previousBusinessDay 연결을 검증하며 공통 캐시로 재사용한다. 단순 평일 추정·지수 날짜만으로 완전성을 인정하지 않는다. 예산 내 근거 확보 실패는 미확인이다.
- 가격·거래량 조정 기준은 공급자에서 검증할 수 있는 자료만 사용한다. 수정·비수정 창이 다를 때 거래량 정규화 근거가 없으면 제외한다. 공급자가 보장하지 않는 가짜 필드를 검증 근거로 요구하거나 신뢰하지 않는다.
- 기존 테스트의 가짜 일봉은 달력일을 연속 생성하므로 거래일 검증 추가 시 공통 휴장·영업일 fixture를 정합하게 수정한다. 운영 검증을 약화해 기존 테스트를 통과시키지 않는다.

## 인수 및 구현 순서

PR0 → PR1 → PR2 → PR3 → PR4-A → PR4-B 순서로 독립 diff와 테스트를 확인한다. 사용자의 2026-09-08 담당 변경에 따라 각 단계의 제품 코드·테스트는 Luna(xhigh) 서브에이전트가 편집하며 Codex 주 에이전트가 설계·검토·독립 검증한다. 최종 인수는 전체 명세의 회귀 표와 실제 진행하는 가짜 시계 통합 테스트로 수행한다.

## 공급자 공개 명세 확인 — 2026-09-08

인증 없이 [공개 OpenAPI JSON](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)을 다운로드해 아래 계약을 확인했다. 실제 장중 응답 검증과는 구분한다.

- `/api/v1/stocks`: 콤마로 구분한 최대 200개 symbols, STOCK 그룹. 랭킹 합집합은 200개 단위 이하로 분할 조회한다.
- 종목 `Candle`과 지수 `MarketIndicatorCandle` 모두 timestamp는 봉 시작 시각이다. 지수 캔들에는 currency가 필수가 아니므로 전용 정규화가 필요하다.
- 두 캔들 API 모두 최대 200개, `before`는 포함 상한이며 응답 `nextBefore`를 그대로 전달한다. 지수 API에는 `adjusted` 옵션이 없다.
- 종목 `adjusted` 옵션은 수정주가 적용 여부만 명시한다. `volume` 설명은 거래량이며 기업행사 전후 조정 방식을 보증하지 않는다. 일봉 종료 시각·수정 거래량을 확인한 것으로 처리하지 않는다.
- 국내 캘린더는 지정 date 기준 today·previousBusinessDay·nextBusinessDay를 제공한다. 지원되지 않는 날짜는 `unsupported-date` 가능성이 있으므로 과거 구간 확보 실패를 완전한 거래일 검증으로 표시하지 않는다.
