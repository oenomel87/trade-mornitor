# 관심종목 프로필 설계

상태: 구현 완료 · 2026-09-05

기존 [관심종목 명령](./watchlist.md)을 프로필별 관리로 확장했다. 이 문서는 구현된 프로필별 사용 흐름과 저장 규칙을 설명한다.

## 목적과 첫 구현 범위

프로필은 이름이 붙은 관심종목 목록이다. `국내주식`, `미국주식`, `반도체`처럼 목적별로 분리하며 같은 종목을 여러 프로필에 등록할 수 있다. 인증 정보·계좌·토큰은 기존 공통 설정을 사용한다.

첫 구현은 프로필 생성·목록·선택·이름 변경·삭제와 기존 관심종목 명령의 프로필 지정까지다. 프로필 복제·병합·내보내기, 여러 프로필 동시 조회, 묶음 분석, 프로필별 분석 설정은 이후 확장한다.

## 사용 흐름

1. 처음 실행하면 `default` 프로필을 사용한다. 기존 관심종목이 있으면 같은 순서로 표시한다.
2. 목적에 맞는 빈 프로필을 만든다. 생성만으로 현재 선택은 바뀌지 않는다.
3. 프로필을 선택한 후 종목을 추가한다. 종목명 검색은 기존 `search`를 사용한다.
4. 목록과 묶음 현재가를 확인한다. 표와 JSON에 실제 사용한 프로필을 표시한다.
5. 다른 프로필을 일회성으로 조회하려면 `--profile NAME`을 붙인다. 저장된 선택은 바뀌지 않는다.

```sh
# 기존 목록 확인: 처음에는 default
tmon watchlist

# 새 프로필 생성 후 선택
tmon profile create 국내주식
tmon profile use 국내주식
tmon watchlist add 005930 005380
tmon watchlist quote

# 선택을 바꾸지 않고 다른 프로필 구성·조회
tmon profile create 미국주식
tmon watchlist add AAPL MSFT --profile 미국주식
tmon watchlist quote --profile 미국주식

# 프로필별 개수와 현재 선택 확인
tmon profile list
```

`profile list`의 표는 이름, 종목 수, 현재 선택 여부, 갱신 시각을 표시한다. `watchlist`의 표는 종목 위에 대상 프로필을 표시한다.

## CLI 계약

| 명령 | 동작 |
| --- | --- |
| `profile [list]` | 프로필 목록 표시. 인자 생략 시 `list` |
| `profile create NAME` | 빈 프로필 생성. 같은 이름이 있으면 오류 |
| `profile use NAME` | 이후 명령에서 사용할 프로필 저장 |
| `profile rename OLD NEW` | 목록·순서를 유지하며 이름 변경. 선택된 프로필이면 선택 이름도 함께 변경 |
| `profile delete NAME` | 비어 있고 선택되지 않은 프로필 삭제 |
| `profile delete NAME --force` | 종목이 있는 비선택 프로필도 삭제 |
| `watchlist [list] --profile NAME` | 지정 프로필의 종목 목록 |
| `watchlist add SYMBOL ... --profile NAME` | 지정 프로필에 추가 |
| `watchlist remove SYMBOL ... --profile NAME` | 지정 프로필에서만 삭제 |
| `watchlist quote --profile NAME` | 지정 프로필만 묶음 현재가 조회 |

- `--profile`은 `watchlist` 계열에서만 지원한다. 하위 명령 앞뒤 모두 허용한다. 예: `watchlist --profile 국내주식 quote`, `watchlist quote --profile 국내주식`.
- `--json`, `--no-color`, `--help`는 기존 규칙을 유지한다.
- 이름은 NFC 정규화 후 1~32자의 한글 음절·영문·숫자·하이픈·밑줄을 허용한다. 공백·경로 구분자는 허용하지 않으며 영문 대소문자는 구분한다. 파일 경로로 사용하지 않는다.
- `default`는 항상 존재하는 예약 프로필이다. 종목 추가·삭제는 가능하지만 프로필 자체의 이름 변경·삭제는 불가하다.
- 현재 선택된 프로필은 `--force`로도 삭제할 수 없다. 먼저 `profile use default` 등으로 전환한다. 삭제 시 다른 프로필로 자동 전환하지 않는다.
- 삭제 명령은 대화형 질문 없이 조건에 따라 실행하거나 오류를 반환한다. `--force`는 비어 있지 않은 목록을 삭제한다는 명시적 의사 표시다.
- 종목 한도는 **프로필마다 200개**다. 한 프로필 안에서는 중복을 제거하고 등록 순서를 유지한다. 한 프로필에서 삭제해도 다른 프로필에는 영향이 없다.
- 존재하지 않는 프로필 지정은 설정 오류다. 오타로 빈 프로필을 자동 생성하거나 다른 목록을 대신 사용하지 않는다.
- 같은 프로필 재선택, 같은 이름으로 변경, 기존 종목 재추가 등 실질적 변화가 없으면 파일과 갱신 시각을 유지한다. 단, `create`의 이름 중복은 오류다.

## 프로필 결정과 실행 과정

대상 결정 순서는 **명령의 `--profile` → 저장된 `activeProfile`**이다. 저장 파일이 아직 없거나 기존 v1 파일이면 가상 상태의 `default`를 사용한다. v2 파일에서 선택 정보가 없거나 잘못되었으면 손상 오류로 처리한다.

1. 명령·프로필 이름·종목 코드 형식을 검증한다.
2. 저장소를 읽고 대상 프로필의 존재 여부를 확인한다.
3. 로컬 조회는 바로 출력한다. 변경은 잠금 획득 후 최신 상태에서 대상을 다시 결정하고 저장한다.
4. 현재가 조회는 대상 이름·종목·갱신 시각을 한 번 읽어 고정한 후 API를 호출한다. 네트워크 응답을 기다리는 동안 저장소 잠금을 보유하지 않는다.
5. 대상 프로필과 결과를 출력한다. 조회 중 다른 프로세스가 선택·목록을 변경해도 시작 시 읽은 목록에 대한 결과임을 유지한다.

`activeProfile`은 OS 사용자 전체에서 공유된다. 한 터미널에서 `profile use`를 실행하면 이후 다른 터미널 명령에도 적용된다. 스크립트나 여러 터미널에서 대상을 고정하려면 항상 `--profile`을 지정한다. 첫 구현에는 환경 변수·프로젝트별·셸별 선택을 추가하지 않는다.

프로필 관리와 종목 추가·삭제·목록에는 API 인증이 필요 없다. 빈 프로필의 현재가 조회는 기존처럼 API 호출 없이 정상 종료한다. 현재가 누락·오류 정책도 기존과 같다.

## 저장 형식

프로필은 논리적으로 분리하되 작은 CLI에 맞춰 기존 설정 위치의 `watchlist.json` 하나에 함께 저장한다. 선택 정보와 목록 변경을 한 번의 원자적 교체로 반영할 수 있고, 프로필별 파일과 별도 인덱스의 불일치를 피할 수 있다.

```json
{
  "version": 2,
  "activeProfile": "국내주식",
  "profiles": {
    "default": {
      "symbols": [],
      "updatedAt": null
    },
    "국내주식": {
      "symbols": ["005930", "005380"],
      "updatedAt": "2026-09-05T10:00:00+00:00"
    }
  },
  "updatedAt": "2026-09-05T10:00:00+00:00"
}
```

- 경로는 기존과 동일하다. macOS는 `~/Library/Application Support/tmon/watchlist.json`, Linux는 기존 XDG 설정 경로를 따른다.
- 루트 `updatedAt`은 선택·프로필 구성·종목 중 어느 것이든 실제 변경된 시각이다. 프로필의 `updatedAt`은 생성·이름 변경·종목 변경 시각이며 선택만 바꾸면 유지한다.
- 아직 저장되지 않은 가상 `default`는 갱신 시각이 `null`이다. 첫 저장 때도 변경하지 않은 가상 기본 목록의 시각은 `null`을 허용한다. 기존 목록 이전 시 원래 갱신 시각을 보존한다.
- 프로필 목록은 `default`를 먼저, 나머지는 정규화된 이름의 코드 포인트 순서로 표시한다. 종목은 등록 순서를 유지한다.
- 디렉터리 `0700`, 파일 `0600`, 기존 `watchlist.lock`과 5초 잠금 제한을 유지한다. 모든 프로필 변경을 같은 잠금으로 직렬화하고 최신 전체 상태를 읽어 수정한다.
- v1의 파일 크기 한도는 여러 목록에 맞게 조정한다. 첫 구현의 v2 크기 한도는 UTF-8 직렬화 기준 1 MiB로 두고, 읽기와 쓰기 모두 검사한다. 초과 시 기존 파일을 보존하고 전체 변경을 거부한다.
- 버전·선택 대상·예약 프로필·이름·중복 JSON 키·종목 중복·개수·시각을 검증한다. 손상 파일을 빈 상태로 초기화하지 않는다.

## 기존 목록 이전

기존 사용자가 명령을 바꾸지 않아도 목록을 이어서 사용할 수 있어야 한다.

1. **파일 없음:** 메모리에 빈 `default`와 선택 상태를 만든다. 목록·시세 조회만으로 파일을 생성하지 않는다.
2. **v1 파일 조회:** 기존 `symbols`를 `default`로 해석한다. 조회는 디스크를 변경하지 않는다.
3. **v1에서 첫 실제 변경:** 기존 잠금 안에서 v1을 다시 읽고 검증한다. 원본 바이트를 같은 폴더의 고유한 `watchlist.v1.<고유값>.bak` 파일에 `0600`으로 저장하고 동기화한 뒤, 요청된 변경을 포함한 v2를 원자적으로 저장한다.
4. **실패:** 백업 생성에 실패하면 변환하지 않는다. v2 교체 전에 실패하면 v1을 유지한다. 백업 후 중단되면 백업만 남을 수 있으며 다음 실행에서 새 고유 백업을 만든다. 기존 백업은 덮어쓰지 않는다.
5. **v2 이후:** v2만 갱신하며 이전 백업을 유지한다. 기존 목록을 여러 프로필로 자동 분류하지 않는다.

변경 없는 요청은 이전도 수행하지 않는다. 변환 시 결과에 백업 경로와 이전 완료 사실을 표시한다. 구버전 CLI는 v2를 지원하지 않으므로 변환 이후 함께 사용하지 않는 것으로 정한다. 복원이 필요하면 모든 CLI 실행을 종료하고 현재 v2를 별도 보관한 뒤 v1 백업을 복사한다. 자동 복원 명령은 첫 구현 범위에서 제외한다.

## 출력과 오류

기존 JSON의 `schemaVersion: 1`과 `watchlist`의 `data` 구조는 유지하고 메타데이터를 추가한다. 저장 파일의 `version: 2`는 출력 스키마 버전과 별개다.

- `watchlist`: `meta.profile`, `meta.activeProfile`, `meta.profileSource`(`explicit` 또는 `active`), `meta.storeUpdatedAt`을 추가한다. `meta.updatedAt`은 대상 프로필 시각, `meta.savedCount`는 대상 종목 수다. 기존 `watchlistFile`과 추가·삭제·누락 코드 필드를 유지한다.
- `profile`: `command="profile"`, `meta.action`으로 작업을 구분한다. `data`는 작업 후 전체 프로필 목록이며 각 행은 `name`, `symbolCount`, `active`, `updatedAt`이다. `meta`에는 저장 경로·현재 선택·저장소 갱신 시각과 변경 전후 이름 등 작업 결과를 표시한다.
- 이전이 일어난 변경 결과에만 `meta.migration`을 추가한다. 값은 `fromVersion`, `toVersion`, `backupFile`이다.
- 입력 오류, 없는 이름, 중복 생성, 예약/선택 프로필 삭제, 비어 있지 않은 프로필의 일반 삭제, 저장소 손상·크기 초과·잠금 실패는 종료 코드 2다. 각각 구분 가능한 오류 코드를 제공한다.
- 일부 시세 누락은 기존대로 `status=partial`, 종료 코드 5다. 빈 프로필 조회는 종료 코드 0이다.

## 구현 순서와 완료 기준

1. 저장소 v2 읽기·검증, 가상 기본 프로필, v1 백업·이전, 공통 잠금과 원자적 저장을 구현한다.
2. 프로필 관리 명령과 표·JSON 출력을 추가한다.
3. 기존 관심종목 명령에 프로필 결정과 `--profile`을 연결한다. API 조회 코드는 재사용한다.
4. 사용자 사용법·도움말·검증 기록을 갱신한다.

검증은 다음 동작을 중심으로 수행한다.

- v1 조회 무변경, 첫 변경의 백업 내용 일치·v2 이전, 실패 시 원본 보존, 파일 없는 상태의 무생성 조회.
- 프로필별 종목 격리·중복 등록 허용·순서·200개 한도, 한도 초과 시 전체 변경 거부.
- 생성 후 선택 유지, 선택 저장, 명시 옵션 우선, 없는 이름 오류, 한글 정규화와 이름 충돌.
- 이름 변경 시 현재 선택 일관성, 기본/선택 프로필 보호, 빈 목록 삭제 및 `--force` 조건.
- 동시 프로필/종목 변경 시 유실 방지, 읽는 시점의 프로필로 현재가 조회, 네트워크 동안 잠금 미보유.
- 파일 권한·링크 거부·손상·크기 제한, 무변경 요청의 시각 유지, 로컬 작업 무인증.
- 기존 명령과 JSON 소비 코드의 호환성, 옵션 위치, 빈 목록·일부 누락 시세 처리.

실제 API 확인은 임시 설정 폴더에서 국내·미국 프로필을 만들어 각각 조회하며 사용자 목록을 변경하지 않는다.
