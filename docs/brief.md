# 시황·주요 뉴스 브리핑

`tmon brief`는 국내 시장 데이터와 Codex SDK 웹 조사를 결합해 한국어 브리핑을 한 번 출력하고 종료한다. 추천 후보 유무와 무관하게 장전·장중·장마감·휴장일에 실행할 수 있다. 기준 시간대는 `Asia/Seoul`이다.

```sh
./bin/tmon brief
./bin/tmon brief --session premarket
./bin/tmon brief --session intraday
./bin/tmon brief --session close
./bin/tmon brief --profile 국내주식
./bin/tmon brief --profile 국내주식 --profile-limit 5 --json
./bin/tmon brief --research off
./bin/tmon brief --refresh --timeout 300
```

Python 3.10 이상과 기존 토스 인증 환경을 사용한다. `TOSS_CLIENT_ID`·`TOSS_CLIENT_SECRET`, 토스 허용 IP 등록이 필요하며 `.env`는 자동으로 읽지 않는다. 웹 조사는 선택 의존성 `openai-codex==0.147.0`과 기존 ChatGPT 로그인을 사용한다. 준비 방법은 [README](../README.md)의 추천 기능 설치 안내를 참고한다.

## 출력 내용

1. 핵심 요약 최대 3줄: 지수 관측과 출처 있는 뉴스 요약
2. 코스피·코스닥 지수와 각 시세 시점의 전 거래일 종가 대비 등락률
3. KRX 시장별 거래대금, 개인·외국인·기관·기타법인 순매수
4. 국내 거래대금·상승률·하락률 상위 각 5개
5. 명시한 프로필의 관심종목 현재가와 관련 주요 소식
6. 주요 뉴스 최대 5건: 사실, 영향 해석, 출처와 게시 시각
7. 향후 7일의 확인된 일정 최대 5건

토스 API가 숫자를 제공하고, SDK는 국내 뉴스와 국내장에 영향을 주는 해외 경제·미국장·금리·환율 소식을 조사한다. SDK가 시세 표나 진입가·목표가를 생성하지 않는다. 뉴스의 `impact`는 사실과 구분한 조건부 해석이다. 같은 사건의 중복 기사는 묶도록 조사하지만 구조 검증만으로 기사 내용의 진실성이나 사건 중복 제거가 완전히 보장되지는 않는다.

## 유형과 거래일

`--session auto`가 기본이다. 실제 토스 시장 캘린더로 선택한다.

| 실제 상태 | 유형 | 시장 자료 기준 |
| --- | --- | --- |
| 정규장 시작 전 | `premarket` | 직전 거래일과 밤사이 소식 |
| 정규장 시작 이상, 종료 미만 | `intraday` | 당일 자료 |
| 정규장 종료 이후 | `close` | 당일 자료와 다음 거래일 준비 |
| 정규장 없음 | `closed` | 최근 거래일과 휴장 중 소식 |
| 캘린더 조회 실패 | `unknown` | 거래일 미확인 표시, 가능한 뉴스 조사 |

휴장·개장 지연을 캘린더로 반영하며 추천의 09:30 진입 평가 제한을 적용하지 않는다. `closed`·`unknown`은 자동 판단 결과이고 직접 지정 옵션은 아니다.

`--session close`를 장전에 실행하는 등 유형과 실제 상태가 다르면 경고한다. 실제 거래일을 바꾸거나 미래의 장마감 결과를 만들지 않는다. NXT 세션별 브리핑은 아니다.

## 숫자와 시각

- 지수: 공식 시장 지표 현재가 API를 사용한다. 현재가 시각이 없으면 별도로 조회한 **완료 1분봉 종가**를 사용하며 `priceBasis=completed-minute-close`, `timeBasis=bar-start`를 표시한다. `asOf`는 공급자의 봉 시작 시각이다. 원래 현재가·시각은 `providerLastPrice`·`providerAsOf`로 보존한다. 전체 브리핑의 `asOf`는 조회 시작 시각으로 고정하고, 각 응답의 실제 `receivedAt`을 기준으로 미래 경계·봉 완료 여부·자료 신선도를 판정한다. 분봉은 시작 후 1분과 5초가 지난 것을 사용한다.
- 등락률: 지수 시세 날짜의 캘린더에서 직전 거래일을 확인하고, 정확히 그 날짜의 일봉 종가로 계산한다. 기준 봉이 없으면 `changePct=null`이다. 당일 일봉을 확정 종가로 사용하지 않는다.
- 지수 분봉은 추천과 같은 완료 봉 검증 함수를 사용한다. 바로 다음 분 경계의 미래 봉은 제외하고 `future-minute-bar-skipped` 경고를 남긴다. 이 경고만으로 브리핑을 `partial`로 처리하지 않으며, 더 먼 미래 봉·완료 봉 부족·기준 일봉 부족·오래된 시세는 계속 데이터 문제로 처리한다. 공급자 현재가에 분봉 시각을 붙이지 않고 완료 봉의 종가와 시작 시각을 함께 사용한다.
- 거래대금·수급: KRX 투자자별 일간 매매대금이다. 네 분류의 매수 합계와 매도 합계가 같은지 확인하고 **매수 합계 한쪽만** 거래대금으로 표시한다. 순매수는 매수−매도이며 단위는 원이다. 당일 기록은 잠정치로 표시한다.
- 랭킹: 토스 제공 집계 범위이며 KRX 수급 표와 범위를 혼동하지 않는다. ETF 등도 포함할 수 있다. 거래대금 랭킹의 등락률은 전일 대비, 상승·하락 랭킹은 1일 기간 시작 대비다. 상위 종목 거래대금 합계를 시장 전체 거래대금으로 쓰지 않는다.
- 한국 시장 자료의 날짜가 기준 거래일과 다르거나 장중 180초보다 오래됐으면 `stale`이다. 장외·휴장일의 정상적인 직전 거래일 자료는 `dated-snapshot`, 시각이 없으면 `unknown`이다.
- SDK 조사가 30초를 넘으면 남겨 둔 예산으로 시황을 다시 조회한다. 갱신 실패 시 이전 관측과 경고를 보존한다. 출력 시점에 신선도를 다시 확인한다. 초 단위 실시간 전송을 보장하지 않는다.
- 미국 관심종목 시세는 자체 시각·통화로 표시하고 한국장 기준 신선도를 부여하지 않는다. 미국장 전체 지수·실시간 환율·해외 금리의 정형 API 표는 이번 범위에 포함하지 않으며 관련 뉴스로 조사한다.

화면과 브리핑 메타데이터의 시각은 KST 오프셋을 포함한다. `inputs.json`의 공급자 원본은 원래 오프셋을 보존한다. 뉴스 게시 시각과 사건 시각은 별도이며 모르면 null이다.

화면은 등락률을 소수 둘째 자리, 큰 거래대금·순매수를 억원으로 표시한다. JSON 금액은 원 단위 십진 문자열을 유지하며 지표는 기존 CLI와 같은 소수 8자리 정밀도로 출력한다.

## 관심종목 프로필

`--profile NAME`을 지정할 때만 그 프로필을 조회·조사한다. 생략하면 시장 전체 브리핑을 만들며 활성 프로필을 자동으로 사용하지 않는다. 활성 프로필·종목 목록은 바꾸지 않는다. 없는 프로필은 네트워크·SDK 실행 전에 오류로 처리하고 빈 프로필에 예시 종목을 넣지 않는다.

기본적으로 저장 순서의 앞 10개를 사용하며 `--profile-limit 1~20`으로 조정한다. `meta.selectedSymbols`·`meta.omittedSymbols`로 범위를 기록한다. 관심종목 뉴스는 전체 5건 안에서 중요도에 따라 포함하며 모든 종목의 뉴스를 보장하지 않는다.

## 뉴스 캐시와 이전 브리핑 비교

모델은 기존 추천과 같은 `gpt-5.6-sol`, 추론 강도는 `high`다. ChatGPT 로그인을 사용하며 API 키 인증으로 자동 전환하지 않는다. 별도 작업 프로세스에 토스 자격 증명·API 키를 전달하지 않는다. 입력은 조사 시각·장 상태·선택 종목 식별 정보이며 투입 금액·계좌 정보는 전달하지 않는다.

조사 범위는 기준 시각 이전 72시간이다. 출처 URL·참조 관계·게시 시각·배열 크기를 검증한다. 미래 게시 자료와 모든 근거가 72시간보다 오래된 뉴스는 거부한다. 게시 시각 미확인 출처는 미확인 상태로 보존한다. 실제 웹 검색 이벤트가 없는 SDK 결과는 사용하지 않는다. 유효한 자료가 없으면 `no-relevant-source`로 표시한다.

뉴스만 캐시하고 시세는 매번 조회한다. 캐시는 장중 10분·그 외 30분으로 조회 완료 시각부터 계산한다. 날짜·유형·선택 종목·모델·추론 강도·프롬프트 버전으로 구분한다. 캐시 사용 시 원래 조사 기준 시각을 표시하며 `--refresh`는 캐시 읽기를 건너뛴다.

이전 비교는 프로필과 선택 종목별로 분리하고 장전→장중→마감 사이에도 이어진다.

| 표시 | 의미 |
| --- | --- |
| 첫 브리핑 | 이전 성공 조사 기록 없음 |
| 이전 브리핑 이후 게시 | 새 출처의 확인된 게시 시각이 이전 조사 기준 이후 |
| 기존 출처 | 원문 URL이 모두 이전 조사에서 확인됨 |
| 추가 확인한 출처 | 새로 발견했지만 게시 시각은 이전 조사보다 과거 |
| 게시 시각 미확인 | 새 출처의 게시 시각을 확인할 수 없음 |

URL의 추적 파라미터와 fragment는 비교에서 제거한다. 같은 URL의 본문 수정이나 사건의 의미상 변화를 자동 확정하는 기능은 아니다. 실패·`--research off`·캐시 조회는 이전 성공 조사 기준을 앞으로 이동시키지 않는다. 비교용 출처 URL은 최대 500개 보존한다.

## 시간 예산·실패·저장

`--timeout`은 30~600초, 기본 240초다. 초기 데이터 조회에 최대 60초를 사용하고 뉴스 조사 뒤 최종 시황 조회에 최대 20초를 남긴다. SDK timeout 시 하위 런타임까지 종료한다. 반복 실행은 ChatGPT 사용량을 소비하며 실제 소요 시간은 환경·뉴스 범위에 따라 달라진다.

| 상황 | 상태 / 종료 코드 |
| --- | --- |
| 정상·휴장일 브리핑 | `ok` / 0 |
| 웹 조사 실패, 시장 자료 정상 | `partial` / 0 |
| 시장 자료 일부 실패·오래됨·시각 미확인 | `partial` / 5 |
| 시장 자료와 뉴스 모두 없음 | 종료 코드 5 |
| 잘못된 옵션·없는 프로필·동일 대상 중복 실행 | `error` / 2 |
| 웹 조사 끄기 | 시장 상태에 따름, `research.status=disabled` |

JSON은 기존 `schemaVersion`, `command`, `status`, `data`, `meta`, `warnings`, `error` 구조를 사용한다. `data.market`·`data.research`를 분리하고 `meta.briefSchemaVersion=1`을 기록한다. 자동화는 종료 코드뿐 아니라 상태·경고·시세 시각·`research.status`를 함께 확인해야 한다.

macOS 기록은 `~/Library/Application Support/tmon/brief/runs/<runId>/`, Linux는 `$XDG_DATA_HOME/tmon/brief/runs/<runId>/`(기본 `~/.local/share/tmon/brief/runs/`)이다. 각 실행에 `result.json`·`inputs.json`·`research.json`이 있다. 폴더 `0700`, 파일 `0600`, 원자적 교체를 사용하고 자동 삭제하지 않는다. 같은 프로필·선택 종목의 중복 실행을 잠금으로 막는다. 저장 권한이 없으면 결과를 출력하고 경고한다.

예약·알림 전송·자동 주문은 이 명령에 포함하지 않는다. 예약 실행기에서 절대 경로의 `bin/tmon brief --json`을 호출하고 결과를 전달하면 된다. 추천 후보는 별도 `tmon recommend` 결과를 결합할 수 있다.

## 검증

```sh
.venv/bin/python -m unittest tests.test_brief -v
.venv/bin/python -m unittest discover -s tests -t .
```

테스트는 임시 저장소와 고정 응답을 사용한다. 장 상태·지수 기준일·수급 계산·프로필 보존·출처·시각·캐시·이전 비교·중복 실행·SDK timeout·느린 조사 후 시세 갱신·부분 실패를 확인한다. 실제 확인 기록은 [구현 검증 기록](implementation-verification.md)을 참고한다.
